## 八组已确认的问题

### AI-01 / P1：完整Agent首轮失败，无法生成分析

复现：管理员进入预警中心，点击“触发分析”，分别填750、346、175，每人提交一次；打开对应“查看报告”。预期为实际工具读取、合法风险/方案落库，按风险等级继续检索/审核或合理短路。实际三个任务均很快“系统异常”，四阶段无产物。

日志证明工具目录可解析为7个工具，首轮模型调用捕获`NonTransientAiException`后被归为`TOOL_ERROR`。**这不证明MCP工具执行失败，也不能确定本次就是历史400/429。** 当前脱敏日志只有异常类，没有实际HTTP状态或固定供应商错误码；本地请求预算/冷却也可能抛同一异常。Groq模型目录只读GET200、所选模型存在；它不证明生成请求可用。LLM成功指标为0，只统计成功响应，不能据此断言没有HTTP请求到达Groq。

修复方向：先增加安全的本地拒绝类别/HTTP状态/error code关联，核对生产首轮实际请求与参数，再针对证据修复；保留严格输出校验、有界重试和共享冷却。通过判据是至少一个真正执行工具并生成有效产物的完整任务，不是健康或目录请求200。具体根因仍待定位。

追加无推理预算核验：BUDGET_PROBE.json（本地测试产物，不入库：`./BUDGET_PROBE.json`）。从实际部署公开资源及7个公共工具schema重建首轮messages约8,782 UTF-16字符，低于18,000上限；配置max_tokens=2,400与输出预算相同。这不是捕获的真实HTTP payload，不能据此完全排除运行时选项合并、实际序列化或冷却差异，也不能证明供应商400。

### AI-02 / P1：学生可以接收其他学生的AI实时通知

复现：用既有`student`演示账户登录，携带有效会话连接`GET /api/agent/api/v1/warning/stream`；保持有界短连接至本次自然产生的task #5终态。预期为403且没有事件。实际HTTP200、`text/event-stream`、hello，然后收到`taskId=5, studentId=175, status=FAILED, riskLevel=null`。该账户绑定的合成学生是张星川，不是student175。

同一会话读取task列表、task3详情和observability均返回HTTP200/业务403，说明SSE遗漏了普通控制器已有的角色边界。此次已证实跨学生任务元数据泄露；没有观察到非空风险值或完整心理报告。源码广播还包含riskLevel，潜在范围与本次实证分开。

修复方向：SSE入口执行教职工授权，注册连接时保存获准范围，事件按权限分发；另定义会话失效/权限撤销后的长连接生命周期。通过判据包括学生新握手拒绝、无他人事件、合法教职工正常接收。已有连接注销后是否即时失效，本次没有单独实测。

### AI-03 / P2：失败不可诊断，页面缺少安全失败类别

复现：打开task3报告与同次站内追踪。实际报告只有“系统异常”“未执行”，没有失败阶段、固定错误类别或trace关联入口。追踪显示DEFAULT/未记录，无法直接辨别本次失败原因。

Langfuse实际上已收到`metadata.status=TOOL_ERROR, iterations=1`，并非没有上报失败；站内代理没有读取这些白名单状态。DEFAULT是观测级别，页面也声明它不代表任务成功。模型/用量为空不单独认定为故障。

修复方向：结构化失败状态落库并在授权页面显示固定分类、安全HTTP/error code及task/trace关联；观测代理只投影固定status/iterations，不开放任意metadata或模型正文。通过判据是可区分本地预算、供应商拒绝、限流、解析、工具和审核等阶段，同时保持内容采集关闭。

### AI-04 / P2：失败终态没有结束时间

复现：读取三个FAILED任务列表/详情及数据库元数据。页面完成时间均为“—”或“-”，`completed_at`均为NULL，只有updated_at变化。预期每种终态都有稳定结束时间，可核算耗时。

修复方向：统一COMPLETED/REJECTED/FAILED终态写入结束时间，并验证重复更新不覆盖原结束时刻。REJECTED当前路径的风险来自源码，本轮未真实产生REJECTED任务。

### AI-05 / P2：任务时间与追踪时间相差8小时

复现：task3创建时间在报告页显示`2026-10-11 03:49:56`，对应追踪按浏览器UTC+8显示`2026/10/11 11:49:56`。相同实际事件被显示为相差8小时；任务列表及面板的Agent待办也显示UTC裸时间。

任务页当前只对字符串替换T并截取，不解析偏移。修复方向：先定义数据库/Java/API时间语义，以带偏移的RFC3339或明确epoch传递，前端一致转换；不能对所有历史日期盲目加8小时。通过判据是同一时刻在任务、报告、待办、追踪及未来PDF上一致。

### AI-06 / P1：知识库只有三条合成探针，业务RAG质量未具备

复现：只读Milvus `count(*)`，case/policy/psychology各1条、success0条；活跃逻辑语料共3条且都带测试标记。物理`num_entities`合计9包含旧版本/删除项，不能宣称有9条有效知识。独立查询召回的就是这三条探针。

这证明机械检索可通，不能证明覆盖教育支持情景或引用质量。修复方向：先准备有明确来源及使用许可的案例/政策/支持知识与覆盖清单，再另行受控入库、检索相关性和引用评估；本次未新增/替换语料。该项属于生产能力缺口，与AI-01生成故障分开。

### AI-07 / P2：RAG返回丢失原始source字段

复现：已有逻辑片段的Milvus `source`非空，独立retrieve返回仅保留`source_db`、标题和片段，不包含`source`。当前source是测试出处标记，不是实际文献URL；本库没有真实URL可以追溯，不能声称删除了原有URL。

修复方向：补齐KnowledgeChunk、Java快照/引用及报告展示的来源契约，区分库名、原始出处、文档标识和可用URL；unknown保持未知，不从标题编造来源。通过判据是检索至报告的出处保持一致且引用可回溯。

### AI-08 / P2：预警表格固定操作列与时间重叠

复现：本次实际1023×1104浏览器窗口、展开侧栏，预警中心有三个任务时，“操作”固定列与创建时间列叠在一起，时间文字覆盖“查看报告”，表头也重叠。截图见上。

修复方向：检查固定列背景/层级、表格实际宽度及横向滚动，确保受限宽度可读、可操作。通过判据是1023窗口、宽桌面与收起侧栏下固定列不透底、不覆盖时间；本次没有修改样式或执行修复后视觉回归。
